# Открытые вопросы и что нужно от команды Лайт-Пак

## Нужно решение или доступ

1. **Тестовый аккаунт / стенд.** Вход, оформление заказа, оплата, заказы, профиль и компании сделаны по контракту,
   извлечённому из старого приложения, и проверены на мок-API (`tools/mock-api.mjs`). На боевом сервере не
   проверялись: без реального номера нельзя получить SMS, а тестовый заказ попал бы в работу. В бандле найден
   стенд `website-stage.service.lite-pack.ru` — нужен доступ и тестовый номер, чтобы прогнать `tools/e2e-auth.mjs` вживую.
2. **Возврат с платёжной формы.** Параметры, с которыми банк возвращает на `/paymentCompleted` (`orderId`, `paymentId`
   или другие), неизвестны — обработчик принимает `orderId|order|id` и `paymentId|payment_id|mdOrder`. Уточнить
   `returnUrl/failUrl`, которые формирует бэкенд.
3. **Логотип в векторе.** На сайте только PNG (лучший — 512 px в иконке манифеста). Сейчас используется вырезка
   451×237 без масштабирования вверх. Нужен SVG — для чёткости на больших экранах и печати.
4. **Тексты, написанные заново** (фактические, без цифр и обещаний — подтвердить или заменить):
   подзаголовок первого экрана «Одноразовая посуда, упаковка и пакеты, бытовая химия и хозтовары — в одном каталоге
   с ценами и остатками вашего региона», блок «Как заказать» (3 шага), подпись «Поддержка клиентов в Ижевске и Нефтекамске».

5. **Ключ Яндекс Карт.** Карта адреса работает и без ключа, но для боевого сайта лучше указать ключ JS API
   (`VITE_YMAPS_KEY` в `.env.local` при сборке) — тот, что уже используется старым приложением на lite-pack.ru.
   С чужих доменов этот ключ мы не проверяли и в репозиторий не кладём.
6. **Консультант «Подбор упаковки».** Правила подбора (какие разделы и слова в названиях, по 1 шт. на заказ) —
   наши, товары и цены — живые. Стоит показать менеджерам: может, у них есть «ходовые» комплекты, которые
   лучше поставить первыми. Пары «основание → крышка» вычисляются по коду модели, размеру и диаметру из
   названий (`tools/pairs.mjs`); ошибочную пару проще всего исправить, уточнив название товара.
7. **Демо-адреса.** В демо-версии (без сервера) адрес по точке берётся из открытого геокодера Photon
   (OpenStreetMap), на боевом сайте — из API магазина, как в старом приложении.

## Серверные настройки (вне фронтенда, дают основной прирост скорости)

5. **gzip для `/api/`.** `v1/categories` весит 170 КБ и отдаётся без сжатия (`docs/nginx.conf`).
6. **Сервис ресайза картинок** (`/{80|180|506},fit/…`): отдаёт только PNG, без `Cache-Control`, генерирует каждую
   картинку заново (0,3–3,4 с). Нужны кэш (proxy_cache) и WebP/AVIF; промежуточный размер ~320 px снял бы LCP < 2,5 с
   на мобильных. Lighthouse (мобильный, медленный 4G): как есть — 91/81/82, с gzip API + кэшем картинок — 91/90/90
   (главная/категория/товар). LCP в симуляции 3,1–3,3 с упирается именно в PNG по 80–150 КБ.
7. **Статус 404.** Несуществующие адреса показывают страницу «Не найдено», но отдаются со статусом 200 (фолбэк SPA).
   Если важно для SEO — настроить в nginx, но тогда новые товары до пересборки тоже получат 404.

## Функции старого приложения, которые перенесены частично

8. **Слияние корзин после входа** («У вас уже есть непустая корзина…», «Объединить корзины»). Эндпоинты для этих
   действий в контракте не нашлись — сейчас после входа показывается сообщение сервера (`appMessage`), если оно есть.
9. **«Позвонить после заказа»** (`callAfterOrder`) — поле есть в модели заказа, но в запросах оформления его нет;
   переключатель не выведен.
10. **Сохранённые получатели** (`v1/orders/receiver`): получатель задаётся при оформлении; отдельного списка нет —
    не найден GET-эндпоинт списка.
11. **Избранное** (`v1/wishes`): реализована подписка «Уведомить о поступлении» для отсутствующих товаров
    (для вошедших). Формат ответа GET не подтверждён — список избранного не выведен.
12. **Счёт на оплату и QR-оплата для юрлиц.** QR из ответа `paymentForm.qrCode` показывается как картинка/текст;
    эндпоинт «Скачать счёт на оплату» не найден.
13. **Карта при выборе адреса.** В старом приложении была карта (Яндекс). Здесь — поиск адреса с подсказками +
    кнопка «Моё местоположение»; карта на «Контактах» — виджет Яндекс.Карт по клику. Для выбора точки на карте
    нужен ключ JavaScript API Яндекс.Карт.

## Как устроено, чтобы не было сюрпризов

14. **Повторный вход.** Токен старого сайта хранился во Flutter-хранилище — после выкатки вошедшим покупателям
    нужно войти по SMS ещё раз. Корзина анонимного профиля тоже начнётся заново.
15. **Пререндер и снимок каталога.** Статические страницы строятся из `data/snapshot.json`; цены и остатки в них
    скрыты и всегда берутся из живого API. Новые товары открываются и без пересборки (как SPA), но в HTML для
    поисковиков попадут после `npm run snapshot && npm run build`.
16. **Контакты офисов** (Ижевск, Нефтекамск) зашиты в коде, как и в старом приложении (`src/hooks/data.ts`).
17. **Не проверялось:** Safari/iOS вживую (тесты — Chromium с мобильной эмуляцией), реальные SMS и оплата,
    поведение с сохранённой сессией старого Flutter-сайта.
    На iPhone нет вибрации, а наклон сцены от гироскопа требует разрешения, поэтому там его нет; покачивание и поворот пальцем работают.

## Фото товаров и 3D (версия 2.1)

18. **Исходники фото.** Из 3437 фото каталога 248 меньше 300 px по короткой стороне и ещё 1186 — от 300 до 600 px.
    `npm run images` делает из каждого улучшенную копию (Lanczos-увеличение не больше ×2,5 + адаптивная резкость,
    WebP 480 и 1000 px) — заметно чётче, но детали, которых нет в исходнике, так не появятся. Лучший результат дадут
    оригиналы от поставщиков (≥1000 px). 3 ссылки на фото в каталоге битые (404 в хранилище: `72f7d304…`, `1329aa09…`, `5c227dd9….23 (1)`) — у этих товаров фото нет и на старом сайте.
19. **Нейросетевое увеличение (Real-ESRGAN x4plus)** проверено на 20 самых мелких фото без надписей
    (`docs/review/ai/`). Прозрачный пластик (стаканы, крышки, тортницы, вилки) — заметно чётче. Но в 5 из 20 нейросеть
    искажает товар: стирает фактуру пенопласта (подложки, тарелка выглядят гладким пластиком) и перекрашивает детали
    (белые ручки крафт-пакета стали коричневыми). **Решение (2026-10-20): не применяем**, остаётся улучшение 2.1
    без нейросети. Для по-настоящему чётких фото нужны оригиналы от поставщиков (п. 18).
20. **3D-модели товаров.** Официальных 3D-моделей у производителей не нашлось (у OSQ на сайте только габариты).
    Вместо «примерных» моделей сделан 3D-просмотр габаритов по характеристикам товара (90 товаров с полными
    размерами) с банковской картой для масштаба. Если появятся GLB/OBJ от поставщиков — их можно показать там же.
